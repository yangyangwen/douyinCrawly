这份清单按“如果你要把这个项目当成对外服务来用”来拆分，优先级从高到低。

## P0：上线前必须补

- [ ] 接口鉴权
  说明：当前 API 默认无鉴权，直接暴露公网风险很高，至少要补 API Key、签名、Basic Auth 或反向代理鉴权。

- [ ] HTTPS / 反向代理
  说明：建议放到 Nginx、Caddy、Traefik 后面，对外统一走 `80/443`，同时做 IP 白名单、限流和日志。

- [ ] 限流与防滥用
  说明：搜索接口和任务接口目前都没有速率限制，对外开放后容易被打爆或触发上游风控。

- [ ] Cookie 生命周期管理
  说明：现在已经支持 GUI 登录获取、`POST /api/settings` 热更新、Docker 环境变量注入，但还没有自动续期和失效告警。

- [ ] 结果与任务持久化
  说明：任务状态、结果列表目前在内存里，服务重启后会丢。对外服务建议落库，至少补 SQLite / Redis。

## P1：尽快补

- [ ] Cookie 有效性检测接口
  说明：代码里已有 `test_cookie_validity()`，但没有暴露成单独 API，也没有在保存配置时做有效性校验。

- [ ] 多账号 / 多 Cookie 轮换
  说明：如果后续搜索或采集请求量大，单账号 Cookie 很容易成为瓶颈。

- [ ] 任务超时、取消、清理机制
  说明：当前任务可启动和查询，但没有明确的取消接口，也没有统一的过期清理策略。

- [ ] 结构化日志与监控
  说明：建议补请求日志、失败率、耗时、Cookie 失效率、上游风控命中率。

- [ ] Docker 健康检查与资源限制
  说明：建议给容器补 `healthcheck`、CPU/内存限制、日志轮转。

## P2：体验优化

- [ ] Web 模式下的 Cookie 获取方案
  说明：当前“登录获取 Cookie”只在 GUI 模式下可用；Web / Docker 仍以手动粘贴或环境变量注入为主。

- [ ] 配置热重载
  说明：现在通过 API 保存配置会立刻生效，但手动编辑 `config/settings.json` 仍需要重启，可以考虑加文件监听。

- [ ] API 文档自动化
  说明：可以直接启用/补充 OpenAPI 示例，方便外部系统联调。

- [ ] 搜索接口分页 / 游标化
  说明：当前同步搜索更偏“一次性返回”，如果后续要给外部系统稳定消费，建议补分页语义。

- [ ] 失败重试策略细化
  说明：把网络错误、Cookie 失效、上游限流拆开处理，而不是统一报错。
